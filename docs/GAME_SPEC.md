## コンセプトと体験 — GAME-001

帰宅するだけのはずのマンションで、いつもの廊下とエレベーターの振る舞いを確かめ、怪しい誘いに応じるか、退けるか、何もしないかを判断して自宅へ戻る、一人称の雰囲気ホラー。

- Windows PC、WASDとマウスに慣れたホラー初心者。静かな自宅が主な環境。
- 未知への不安 → 手がかりと対処を理解する怖さ・納得 → 慣れた人の手際のよい攻略、という変化を許容する。最後まで同じ恐怖量を維持する義務はない。
- 雰囲気を楽しむ人も、怖がらない人も遊べる。理不尽な失敗、過剰な説明、無意味な待ち時間を避ける。
- 初回全体で死亡・再挑戦込み10〜20分を目標とする。意図的な長時間放置を含む保証ではない。
- 参考は8番出口、リミナルスペース、Anemoi Apolis、Escape the Backroom、エレベーター都市伝説。模倣する個別ルールや素材の採用ではない。

| 区間 | プレイヤーの行動 | 狙う感情 |
|---|---|---|
| 導入夜 | 掲示を読み、通常の8階廊下を見て帰宅 | 日常の把握、薄い違和感 |
| 怪異夜1 | 基本3系統を見分け、誤りから修正する | 不安、判断の迷い、理解の入口 |
| 怪異夜2 | 各系統の別表現に同じ原則を適用 | 疑い、理解の応用、納得 |
| 最終夜 | 既知の手がかりで順序・表現の変化に対処 | 緊張と習熟、上手く帰れる満足 |
| 終了 | 帰宅成功、結果を確認 | 安堵。ただし怪異の消滅は断定しない |

## 全体の進行 — GAME-002・003・010

1. タイトルから新規開始または続き。
2. 毎夜マンション入口のエレベーターホールで開始。呼びボタンで開け、乗り込み、8階を選ぶ。
3. 導入夜は危険な怪異なし。正常な帰宅と基準廊下を経験する。薄い違和感は可。他階が使えないことを怪異に捕らわれた状態として扱える。
4. 怪異夜では所定の遭遇を処理して、本物の8階へ到着する。
5. 降りて自宅ドアにインタラクトすると夜クリア。暗転し次夜へ。
6. 死亡は演出・暗転を経て現在夜の入口ホールへ。クリア済み夜を失わない。
7. 最後の夜をクリアして結果 → 短いスキップ可能なスタッフロール → タイトル。

必須は導入1夜＋怪異3夜の全4夜。怪異夜の通常遭遇数は3・3・3、各夜各系統1回。各系統2表現、計6パターン。

- 怪異夜1: 基本の3パターン、配置順固定。
- 怪異夜2: 別表現の3パターン、配置順固定。
- 最終夜: 各系統の表現と出現順を抽選。死亡時も再抽選。
- 早期2夜の具体的な固定順は試作配置として記録し、効果を評価する。
- 通常走行中の非常停止による追加遭遇は通常枠に数えない。最初の怪異夜から全6パターンを候補とする。
- 全怪異に出会うこと・タイム短縮はリプレイの動機。専用図鑑やオンラインランキングを必須にしない。

## 舞台と経路 — GAME-011

- 現代日本の郊外。築約40年、10階建ての大きなマンション。人が住んでいるが手入れ不足。廃墟にはしない。
- 主人公は仕事から帰宅する住人。自宅は8階。
- エレベーター出口正面からまっすぐ伸びる廊下。本物の見分けに使う形・配置・特徴は毎夜同じ。
- 室番号がかご内から読めることを必須にしない。自然に見える廊下全体の姿を基準にする。
- 消火設備や突き当たりの窓は候補であり配置確定ではない。柱や濡れなど様々な差を使える。
- 階段・退出経路へ進むと同じホールへ戻る空間ループ。単に鍵で封鎖する解決にしない。必要な短い接続通路までを制作し、屋外全域は不要。
- 本物の廊下の識別はかご内の移動・視点操作で可能にする。判別前に危険域へ出ることを強要しない。

## 操作・情報提示 — GAME-004・009・013

- WASD移動、マウス視点、左クリックで即時インタラクト。長押し確定を廃止する。
- 歩きと走り。スタミナなし。具体的な速度・感度・キー割当は試作値として記録する。
- 中央の小さな点と操作対象ボタンの反応。通常プレイ中の正誤ラベル、説明オーバーレイ、常時計時、長押しゲージは不要。
- 少数の基本原則をホールまたはエレベーターの掲示で教える。全編で原則は有効。難しさは状況の認識に置き、途中で隠れたルール反転をしない。
- 機械表示・音・廊下の姿を比較して判断できる。雰囲気のために必要情報まで隠さない。
- 正しい理解に基づく操作は信頼できる。嘘の案内は可だが、正しい操作の因果を恣意的に裏切らない。

## 怪異と対応 — GAME-005〜008

同時に対処を要求する系統は1つ。複合怪異は基準版に含めない。「何もしない」も正解として扱える実装が必要。

| 系統 | 信頼できる識別情報 | 初期の正解 | 初期の誤対応 | 必須表現 |
|---|---|---|---|---|
| 誘引 / Lure | 8表示・正常停止でも、基準廊下と異なる | かご内に留まって閉ボタン | 敷居を越えて廊下へ出る、非常停止 | 異常な柱／明確な濡れ |
| 挑発 / Provocation | 閉扉走行中、非常停止を押すよう誘うが、本物の暴走の表示と音の組合せがない | 押さずにやり過ごす | 閉ボタン、非常停止 | 設備放送／外から助けを求める声 |
| 乗っ取り / Hijack | 閉扉走行中、表示が8を越えて上昇し、走行音も上がる・速まる | 非常停止 | 閉ボタン、放置による期限超過 | 機械の暴走／かご内の空間異常 |

### 誘引

- 偽到着は8階表示・通常の停止。階数だけでは見破れない。
- かご内で観察・待機しても危険が進行しない。敷居を越えたら誤対応確定。
- 初回誤対応後は変貌と明瞭な手がかりを提示し、修正猶予を与える。
- 修正は「身体をかご内へ戻す＋閉ボタン＋閉扉完了」。戻るだけでは解決しない。
- 外から閉ボタンを押すと扉が閉じて死亡する。
- 帰路と操作盤を判別可能に保つ。修正不能になるほど必要距離を恣意的に伸ばさない。
- 接近する暗闇、表面変化、伸びる廊下は演出候補。全部を必須にしない。

### 挑発

- 文字の矛盾探しより、「押したら安心できそうだが我慢する」が中心。
- 誘い先は非常停止で統一。本物の乗っ取りと同一の決定的合図を偽装しない。
- 誤対応で誘いが強まり、修正猶予中は何も押さず耐えれば生還する。
- 無操作・放置でも助かることを許容する。放置防止の隠し罰則を足さない。

### 乗っ取り

- 2表現とも「8階を越える表示＋上昇・加速する走行音」を保つ。
- 空間異常でも操作盤と必要情報を失わせない。
- 初回期限超過または閉ボタンで悪化し、手がかりと修正猶予。猶予内の非常停止で救済、期限超過で死亡。

## 誤対応・入力・扉の境界 — GAME-006・007

- 初回誤対応 → 正体・危険と明瞭な手がかりの提示 → 修正入力受付。提示前のクリックは無視し、先行入力を持ち越さず、2回目の誤りにも数えない。
- 修正猶予中にもう一度誤った対応ボタンを押すと全系統で即死。無効な開ボタン・階ボタンを誤答として数えない。
- 正解受理後の解決・遷移中の追加入力を新しい誤答にしない。
- 後半夜は猶予を少し短縮。判断が速ければ歩きでも修正可能、走りは余裕になる設計を守る。
- 扉に人が挟まる通常の閉扉は中断して再開扉。
- 誘引の猶予内に身体を戻して正しく閉操作を受理したら、残りの閉扉処理だけが旧期限を越えても死亡させない。生還確定は閉扉完了。
- 身体が扉を妨げて再開扉したら未解決へ戻り、残り猶予を再開する。外からの閉操作による死亡は別の明示ルール。
- 敷居判定範囲、閉扉所要時間、猶予秒数は上記条件を満たす試作値。ログへ状態・受付可否・残り時間を残して検証する。

## 正常時とボタンの例外 — GAME-008

| 状態・操作 | 振る舞い |
|---|---|
| 夜開始の乗車後、8階選択 | 出発 |
| 他階ボタン／出発選択以外の階ボタン | 無効。死亡・怪異を起こさない |
| 通常停車時の開 | 有効 |
| 走行・怪異・解決中の開 | 無効。誤答に数えない |
| 通常走行中の閉 | 追加怪異なし |
| 本物の8階で降りず閉 | 安全に再提示。時間はかかるが閉だけで追加怪異なし |
| 通常走行中の非常停止 | 短く停止して自動再開。受理1回につき約33%で追加怪異 |
| 停止中の非常停止連打 | 追加抽選なし。再開後の新たな受理で再抽選 |
| 乗っ取りに正しく非常停止 | 短く停止して自動再開。通常走行の抽選は行わない |
| 導入夜の非常停止 | 危険な追加怪異抽選なし |

- 追加は全6パターンから均等。通常の初期状態で出し、いきなり修正猶予から始めない。
- 誘引は到着・開扉、他2系統は閉扉走行という成立条件を守って挿入する。同時発生にしない。
- 追加はその夜の通常ノルマに加算されるため帰宅が遅れる。
- 掲示は不要な非常停止の危険を伝えるが、33%という数字は表示しない。

## 映像・音・物語 — GAME-012・013・015

- 写実寄りの日常的な比率と素材の統一。AAA品質や強いレトロ加工を必須にしない。
- 通常は白い蛍光灯で必要なものが見える。暗さ・敵数・ジャンプスケア増加を恐怖の自動的改善と見なさない。
- 空間・機械が中心。人影は必要なら使うが、精密な怪物モデルは不要。
- 予兆のある急変は可。無予告の画面いっぱいの顔などは避ける。
- 環境音中心。音楽はタイトル等で必要なら。ヘッドホン推奨だがスピーカーでも攻略可能。
- カメラ揺れ・ブラーは必須でない。使うなら軽減・無効化でき、無効でも必要な合図が残る。
- 原因は説明しきらず短い断片。生活・工事のお知らせ等は任意読書。基本ルール掲示と真の識別基準を物語の都合で嘘にしない。
- 帰宅成功は明確、怪異が本当に去ったかは曖昧でよい。
- 台詞、具体レイアウト、死の演出、素材、速度・時間などは承認済み機能・公平性の範囲内で試作し、採用は人の評価と分ける。

## 保存・メニュー・結果 — GAME-010・013

- 夜境界で進行保存。中断した夜は冒頭から。クリア済み夜は維持。
- 続きでも累積死亡数と経過時間を維持し、中断で不利な時間を帳消しにしない。
- 計時は怪異3夜。死亡・再挑戦を含み、ポーズ・ロードは除外。導入夜は含めない。
- 結果は時間・死亡数・ローカル自己ベスト。クリア後は導入をスキップ可能、比較対象は常に怪異3夜。
- ランダム性を含む自分向けの挑戦。厳密な同条件競技・専用TAモード・ネットランキングは必須でない。
- タイトル: 新規／続き／設定／終了。ポーズ: 再開／設定／タイトル。ポーズでゲーム進行と計時を止める。
- 進行上書き・放棄は短く影響を表示して確認。破損・読めないセーブを黙って削除・上書きしない。
- 必須設定: 感度、視点反転、FOV、明るさ、音量、表示設定。具体的な設定範囲・レイアウトは試作記録。

## 制作条件と優先順位 — GAME-014

- Unity 6000.3.14f1 / URP 17.3.0、既存Input Systemと環境を再利用。
- Windows専用GPU搭載PCで1080p・60fpsを目標。最低GPU/CPU/OSの保証は実測後。高性能な開発PCだけで最低環境を認定しない。
- 2026-09-21発表: 正常参照＋基本3系統各1＋誤対応修正・死亡・再挑戦・帰宅を短く遊べる縦切り試作。
- 10月: 学内用完成を目標。12月上旬: 学業上の最終完成期限、正確な日付は未確認。
- 本当の最終版は有料販売を目指す。学内版と販売版は段階を分け、ストア・価格・発売日は学内評価後に決める。
- 販売版もまず全4夜の品質で評価する。拡張しなければ販売できない、とは決めない。
- ユーザーの参加は週10〜20時間程度。Codex稼働20時間以上と人の制作時間は同一視しない。
- 3D・音楽制作技能は前提にしない。無料素材優先、生成AIは実用性を試して判断。Blender/Cubase所持は制作能力の証明ではない。
- 追加費用は総額1万円以内を優先、必要で大きな効率化がある場合のみ2万円以内を検討。購入の包括承認ではない。
- 必須を先に完成。追加夜、遭遇数3/4/5、階ボタン応用ギミック、演出追加は余裕と評価次第。
- PADは小さい労力で実装・実機確認でき、必須を遅らせない場合。重要音の字幕は追加夜・演出よりも後の最終優先。基準版を聴覚アクセシビリティ対応済みと称さない。

## 完成の定義

1. 仕様基準版: 核・全行程・主要ルール・例外・制作範囲がつながり、保留と実験が明記されている。本書の状態。
2. 技術完成: 必須行動が通常入力とWindows Playerで成立し、関連テスト・画面・保存・性能等の証拠がある。現時点で未達。
3. 体験受入: ユーザーが初見の演出を遊び、理解・理不尽さ・怖さ・退屈さを評価し、必要な修正を終える。現時点で未達。
4. 学内完成: 必須内容＋技術検証＋人の体験受入。販売完成は別途リリース条件を決定。

実験は [PLAYTEST_PLAN.md](PLAYTEST_PLAN.md)。ユーザーは仕様を知っているため完全なルール初見者ではない。外部初心者の検証がなければその限界を残す。

## 観測された既存実装との相違

2026-09-06〜07の観測。作業時には必ずコード・シーンを再読する。

- PlayerLook: WASDとマウス視点。InteractionRaycaster: 左長押し・円形ゲージ。即時クリック仕様への移行が必要。
- BeatDefinition: 系統・正解・秒数・表示階・Prefab。既定秒数は仕様承認ではない。
- BeatStateMachine: travel/arrival/diagnosis/commit/reveal/grace/resolve/depart。新仕様の受付境界との一致は未検証。
- ResponseEvaluator: Normal+PressCloseの再提示があるが、Noneを誤答扱いする既存経路があり、無操作成功に対応が必要。
- RunManager: 順序Beat、デバッグ入力、再開・クリア。4夜・追加遭遇・保存・計時との一致は未検証。
- ElevatorController: 扉移動、走行音、揺れ。身体判定・挟まり・閉扉確定との同期は新たに確認・実装する。
- Main / Sandboxや既存Utilityを保護する。以前のテスト成功は新仕様の完成証拠でない。
