# M4-01 保存・再開の実装案

状態: 2026-09-20、前回提案に対するユーザーの「良い感じ、続けて実装」で採用。自己ベストはuser-inputで最短時間と最少死亡数を別々に記録と決定。

## 推奨方式

PC内の `Application.persistentDataPath` 以下に、版番号付きJSONを保存する。現設定では会社名DefaultCompany／製品名GraduationProjectのWindowsユーザーデータ領域。クラウド・ネット送信・新依存なし。UnityのJsonUtilityと標準ファイルAPIを使う。

- `progress.json`: 現在夜、累積死亡数、怪異夜の累積時間、進行中／完了状態。夜の途中を再開すると、その夜のホールから再試行する。
- `profile.json`: 全夜クリア済みフラグ、独立した最短時間／最少死亡数、設定。新規開始でも自己ベストと設定は残す。
- 各ファイルの一時書込みと直前バックアップで保存中断に備える。読めないデータ・未知の版は自動削除／初期化せず、元ファイルを保持して画面で知らせる。
- 夜境界、死亡、ポーズ、タイトルへ戻る／正常終了で記録。怪異夜の時間は短い間隔でも保存し、異常終了で失う時間の上限を明記する。ポーズ・ロード・導入は計時外。夜の途中の怪異構成は保存せず再試行ルールに従う。
- Editor／自動テストの保存先はPlayerから分離。テストは専用一時フォルダーを注入して既存データに触れない。

PlayerPrefsへ進行を集約する方式は少量の設定には簡単だが、進行の検証・版管理・バックアップを明示しにくい。今回は小さなJSON保存層で既存進行を拡張する方針を推奨する。

## 変更範囲と順序

1. 小さな保存DTO／読込・検証・書込み層、HomecomingCampaignへの再開・累積記録接続。既存デモは従来どおり保存しない。
2. DemoSessionの既存メニューを、新規／続き／設定／終了、再開／設定／タイトルへ接続。上書き・放棄の確認、セーブ読込失敗の表示を加える。文章は作者が編集できる既存の文章編集へ配置する。
3. 全夜帰宅後の時間・死亡数・自己ベスト、既クリア時の導入スキップ。先に既定ルールを満たす最小画面に留め、演出・文章の最終採用は人の評価で行う。

## 検証とリスク

- 正常保存／読込、夜境界・夜途中再開、累積時間／死亡数維持、導入・ポーズ・ロードの計時除外、初回・再クリア、設定反映。
- 空／破損／将来版／書込み不可／途中書込みを一時データで再現し、正常なバックアップと不明なデータを勝手に失わないことを確認。
- Windows Playerの終了→再起動→続きまで実確認する。コンパイルやEditor試験だけで保存対応完了とはしない。
- 初回の新保存形式になるため、今後の形式変更には移行方針が必要。製品名・会社名を変更すると保存先も変わる点を記録。複数Playerの同時起動時は上書き競合を検出し、黙って後勝ちにしない。

外部公開・既存データ削除は今回の採用範囲外。

## 実装中の保守メモ（2026-09-20）

- 保存層は `CampaignSaveStore.cs`、ゲーム／メニューへの接続は `DemoSessionPersistence.cs`。既存のメニュー描画はDemoSessionで共有し、RunManagerの死亡通知を一度だけ加算する。HomecomingCampaignは夜構成の担当のまま。
- JSON外枠にversion=1、kind、payload、SHA-256整合性値。暗号化・不正防止ではなく、破損や異種ファイルの取り違え検出用。各値の範囲も検査する。
- `session.lock`をFileShare.Noneで開き、同じ保存先への二重起動を拒む。空のlockファイルは終了後も残るが、OSのファイルハンドルが所有権なので残存自体は故障ではない。
- 書込みは同じフォルダーの固有pendingファイルへflush後、既存mainをFile.Replaceで直前の`.bak`へ退避して置換。中断したpendingや読めないmain／backupは自動削除しない。破損時の自動復元は行わず、手動調査後に別途対応する。
- 全夜クリア時はcompleted進行→profileの順に保存。間に異常終了した場合、次の読込でcompleted進行から独立した最小値を再集計する。進行とprofileを1ファイルへ統合する必要はない。
- 怪異夜の通常進行は10秒ごと、死亡・ポーズ・夜境界・正常終了で保存。異常終了では直前10秒程度の計時を失う可能性がある。保存失敗後は画面で通知し、そのセッションで再書込みを続けない。
- Editorは `artifacts/editor-saves/Homecoming`、Playerは `Application.persistentDataPath/Homecoming`、テストは `artifacts/m4-01/tests/<固有ID>` に隔離。テスト用の保存先差替えはUNITY_EDITOR内だけで、Playerには含めない。
- 新しい文章は「テキスト編集」の `11_保存・続き・結果`。追加メニューは既存の値を上書きせず、見つからないキーだけ追加する。結果の数値とキーは文章編集で変更しない。
