# ゲーム内の文章を書く

## 本編冒頭の制作（OPENING-001）

本編用は `Assets/Scenes/Homecoming.unity`。既存の `PlayableDemo` は保持し、自動同期しない。Homecomingでは導入説明の本文を出さず、805の郵便受けを調べてからオートロックへ805を入力するとホールへ進める。取消ボタンで入力を消す。誤番号は短い赤表示の後に再入力可能。翌夜と死亡再開はホールからで、郵便受けを繰り返し調べる必要はない。

- 文章編集→`09_入口・ポスト・オートロック`：ポスト番号・キー表記。文章の編集だけでは入力判定の番号は変わらない。
- `EntranceHall > 入口_集合ポストとオートロック > 入口操作_805を調べて入力`：有効番号、自動扉の速度・移動量・操作音量。
- `本編_入口と夜の進行`：開始のフェード秒数、翌夜までの暗転秒数。翌夜の説明メニューは本編では使用しない。文章編集03の項目は既存デモ用として保持。
- `Player > Nearby Interaction Markers`：▲の大きさ。近距離・遮蔽判定は操作Raycastと同じ基準を使用。

本編のタイトルは既存名「帰宅」を仮置き。新しい物語文・独白は追加していない。掲示は作者の現状を複製しており、三系統の判別と救済を十分伝えるかの文章評価は引き続き必要。

本編のWindows版は、保存後に `Tools > Unity Agent > Build Homecoming Windows` で作る。通常のビルド設定の入口は既存デモのまま保持し、このメニューでHomecomingだけを指定する。生成先は `artifacts/builds/<日時>/GraduationProject.exe`。エディター用テストコードを含まない通常ビルドで、公開・リリースではない。

## 編集の入口

1. `Assets/Scenes/PlayableDemo.unity` を開き、Playを停止する。
2. Hierarchy最上部の **★文章編集_ここから** を選ぶ。
3. Inspectorのカテゴリボタン、またはHierarchyの子オブジェクトを選び、文章欄を編集する。
4. **Ctrl+Sでシーンを保存**し、Playして表示を確認する。

見つからない場合は `Tools > Unity Agent > 文章編集を開く`。起動画面のCanvasはPlay時に生成されるが、その文章はこの常設オブジェクトに保存される。C#の編集は不要。

| カテゴリ | 編集する文章 |
|---|---|
| 01_起動画面 | タイトル、導入本文、操作説明、開始・設定・終了ボタン |
| 02_一時停止・確認 | ポーズ、やり直し・終了の確認、各ボタン |
| 03_翌夜・結果 | 翌夜、帰宅、読み込み、再プレイ・終了 |
| 04_設定画面 | 設定項目、オン／オフ、画面切替、説明・戻る |
| 05_案内・怪異・階数 | かご内の待機案内、停止を誘う文章と正体判明後の文章、帰宅表示、階数の書式、表札 |
| 06_操作盤・かご内表示 | ボタンの文字、定員、注意、案内見出しなど |
| 07_ロビー・廊下・その他表示 | 自宅・階の表示、旧試作用の非表示テキストなど |
| 08_掲示物の見出し・本文 | ロビーの3枚の掲示。本文・見出し・文字サイズ |

館内表示の項目には表示元のHierarchyパスを記載。「表示オブジェクトを確認」で場所を確認できる。非表示の旧試作用も残しているが、文章の変更だけではそれらが表示されるようにはならない。表札も使用している構成でのみ表示される。

## 保存・表示について

- Play中の変更は停止すると失われる。必ず停止中に執筆する。
- 文章は**シーンごと**に保存。デモはPlayableDemoを編集する。M1/M2は個別確認用で、自動同期しない。
- 空欄も保存される。空欄ボタンでもクリック機能は残るため、操作用ボタンには意味が分かる名前を付ける。
- ボタンの文章を変えても、行先階・操作・怪異の判定は変わらない。例えば「８」を「９」と書き換えても行先は８階。
- 動的な現在階は `{0}` を使用する（例：`{0} 階`）。不正な書式の場合は階数のみを表示する。
- メニューは改行・折り返しに対応し、長文はマウスホイールでスクロールできる。掲示・操作盤は固定の紙面／枠なので長すぎる文章は短縮や改行で調整する。
- 館内表示の紙面超過はInspectorに警告する。実際のGame Viewでも確認する。Rich Textタグ（`<size>`等）は表示装飾に使用できる。
- 文章編集欄が表示の正本。子のTMPや古いスクリプトの文字欄を直接編集すると、文章編集欄の内容が優先される。
- 3枚の掲示は `EntranceHall > 掲示物_文章編集はこちら` の各 `EditableNotice` からも編集可能。カテゴリ08は同じデータへの入口で、二重保存ではない。
- `Apply Apartment Visual Pass` は執筆済みの内容を保持する。シーン自体の作り直し・文章編集オブジェクトの削除は保持対象外。
- **既存のexeには反映されない**。保存後、`Tools > Unity Agent > Build Playable Demo Windows` で再ビルドする。配布にはexeと同じフォルダーのData等も必要。

## 現在のルールとの対応

執筆の内容はユーザーが決める。文章だけを調整する際の現行動作は以下。

- 普段の廊下を導入で覚え、８表示だけで降りない。違う廊下なら車内で「閉」。
- 放送・呼び声だけを根拠に非常停止しない。挑発では入力しない。
- ８を越える階数表示と、速く高くなる走行音の両方があれば非常停止。
- 誘引の救済は全身を車内へ戻して閉じ切る必要がある。外から閉めても正解にならない。

文章の分かりやすさ・初見理解・怖さは、実際のプレイ評価で確認する。

## 音と到着タイミングの調整

Hierarchyの **音・動作調整** を選ぶ。Inspectorの `Elevator Tuning` で、走行音・扉の動作音・到着チャイム・怪異の走行音・足音・換気音を0〜1で調整できる。個別AudioSourceのVolumeは演出用の増減で上書きされるため、この欄を使う。

同じ場所で **チャイムから開扉まで**（初期1.4秒）と **怪異の階数上昇間隔**（初期1秒）を編集できる。Play中に試す場合も、保存したい値はPlay停止後に設定し直してCtrl+S。設定画面の「音量」は全体音量で、このInspectorの各音の比率と併用する。

文章編集rootを「テキスト編集」などに改名しても編集入口は識別される。上の `★文章編集_ここから` は初期名称であり、ユーザーが付けた名前が優先される。

## かご内モニターのスライドショー

Hierarchyの `テキスト編集`（初期名は `★文章編集_ここから`）→ `05_案内・怪異・階数` を選ぶ。「かご内モニター：最初の文言」が従来の文章で、その直下に追加文・時間設定がある。「モニター本体を選択」からも同じ設定を編集できる。

- **追加の文言（＋で追加）**: リストを開き＋で追加、−で削除、ドラッグで順番を変更する。改行も保存される。最初の文言→追加リストの上から順→最初の文言へ循環。
- **1枚の表示時間（秒）**: 完全に表示してからフェードアウト開始まで。初期値5秒。
- **片道のフェード時間（秒）**: 消える時間と現れる時間それぞれ。初期値0.5秒なら切替全体は約1秒。大きいほどゆっくり、0なら瞬時切替。

文章は作者が執筆する方針なので追加リストは初期0件。既存文は保持され、＋で文章を増やすとスライドショーになる。1枚だけなら点滅させず常時表示。空欄を追加すると空白の1枚として扱う。文字枠は従来のままなので短い文と改行で調整する。

怪異の案内表示が通常スライドより優先し、終了後に最初の文言から再開する。怪異の提示時間・対応ルールはこの設定では変わらない。一時停止中は進行しない。Play停止中に編集してCtrl+Sでシーンを保存する。M1/M2/PlayableDemoの設定は各シーン独立、既存exeへ反映するには再buildが必要。
